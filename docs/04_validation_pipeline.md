# 04. 検証パイプライン設計+過剰最適化防止

## ステージゲート(全戦略共通・スキップ禁止)

```
IDEA → BACKTEST → OUT_OF_SAMPLE → WALK_FORWARD → STRESS_TEST
     → PAPER_TRADE → [ユーザー承認] → MICRO_LIVE → [ユーザー承認] → APPROVED
```
全ステージでライブ発注禁止(MICRO_LIVE以降のみ極小リスクで可、要ユーザー承認)。

## 各ステージの合格基準

### BACKTEST
- データ:最低2年分(複数レジームを含む)。開発用(イン)と検証用(アウト)を**着手前に分割**。
- コスト算入:スプレッド(保守値0.4pips)+スリッページ0.3pips+スワップ+AIコスト配賦。
- サンプル:最低100取引(頻度が低い戦略は最低60+期間3年以上)。
- 合格:net_EV_R >= +0.15、PF >= 1.3、最大DD許容内、単一日/単一イベント依存なし。

### OUT_OF_SAMPLE
- 開発に一切使っていない期間で実行。パラメータ変更禁止(変更したらBACKTESTへ差し戻し)。
- 合格:net_EV_R > 0 かつ インサンプル比の劣化が50%未満。

### WALK_FORWARD
- 6ヶ月訓練→3ヶ月検証のローリング、最低4窓。
- 合格:全窓の合算net_EV_R > 0、かつ 3/4以上の窓でプラス。
  1つの窓が利益の70%超を占める場合は不合格。

### STRESS_TEST
- スプレッド×2、スリッページ×3、約定遅延+2秒相当、AIコスト×1.5、
  勝率−5%pt を同時適用。
- 合格:net_EV_R >= 0(ゼロ以上で可。マイナスなら不合格)。
- 追加:2022年秋(介入局面)、指標急変日を含む区間での挙動確認。

### PAPER_TRADE
- 実相場でシグナルのみ記録。最低20シグナルまたは2週間。
- 実測スプレッド・想定約定・AIコスト込みnet_EV・NO_TRADE判断を全記録。
- 合格:実測net_EV_Rがバックテスト値の50%以上、ルール違反0件。

### MICRO_LIVE(要ユーザー承認)
- 1取引リスク <= 1,250円、日次損失 <= 5,000円、3敗で停止。
- 合格:スリッページ実測が想定1.5倍以内、想定外挙動0件、AIコスト想定内。

## 過剰最適化防止ルール(Skeptic Agent判定基準)

以下のいずれかに該当 → REJECTED または RESEARCH_ONLY:

1. **パラメータ感度**:主要パラメータ±20%変化で net_EV_R が符号反転する
2. **利益集中**:上位5取引が総利益の50%超 / 特定数日・特定イベントで大半を稼ぐ
3. **サンプル不足**:有効取引 < 60
4. **コスト脆弱**:スプレッド+0.2pips悪化 または AIコスト算入で期待値消滅
5. **IS/OOS乖離**:OOSでの劣化が50%以上
6. **レジーム限定**:単一レジームでのみ機能し、説明可能な仮説がない
7. **複雑性**:エントリー条件が6個超 / フィルター追加で過去成績だけが改善した履歴
8. **仮説欠如**:「なぜ期待値があるか」の市場構造的説明ができない
9. **AI依存**:Fable5の裁量的判断なしに機械実行できない

## パラメータ探索の上限(無限探索の禁止)

- 1候補あたりの探索組み合わせ:最大50通り
- 探索前に「経済的に意味のある範囲」を仮説として文書化してから探索する
- 最良値ではなく「プラトー(安定領域)の中央値」を採用する

## 既知のルックアヘッド落とし穴(2026-07-08追加・実際に発生した事例)

**事例(C016)**: JST日付でグルーピングしたバー列は0:00 JST始まりのため、
「utc_min >= ロンドン開場時刻」のような単純なUTC分条件は、当日東京セッション
より前の深夜バー(JST 0:00-8:59)を拾う。シグナル(東京レンジ)確定前の
エントリーとなり、IS EV_R +1.14という偽の好成績を生んだ。
**対策(Skeptic審査の必須手順に追加)**:
1. 上位10取引のエントリー時刻を目視し、シグナル確定時刻より後であることを確認する
2. エントリー時刻の分布を確認する(想定時間帯以外のエントリーは実装バグを疑う)
3. 「成績が異例に良い」こと自体をバグの兆候として扱う(EV_R > 0.5/取引は要精査)

### 大規模スクリーニング実施時のチェック(2026-08-10追加・上記の再発防止)

サブエージェント等に一括測定を委託する場合、**指示文に次の4点を明記してから起動する**:
1. 使用可能なデータ期間を**開始日と終了日で明示**する
   (「〜以前」ではなく「2023-01-01〜2025-06-30のIS期間のみ」のように書く)。
   旧OOS(2025-07〜2026-06)と未来データ(2026-07以降)を名指しで禁止する。
2. 測定コードを research/ にコミットさせる(再現不能な数値は主張として採用しない)。
3. N本同時測定の**選択効果(winner's curse)**を結果に明記させる。
   上位の点推定は上方バイアスを持ち、解禁判断の根拠に使えない。
4. 結果は「探索的スクリーニング=合格判定に使用不可」の格付けで記録する。
   合格判定は事前登録(strategies/candidates/batch_00N_prereg.md)を経た検証のみ。
- 今後パスする候補には、OOS EV_Rの95%信頼区間が0を上回ることを追加要求する
- 最終的な昇格判断はペーパートレード(未使用の未来データ)の実測を主とする

## データ品質チェック(バックテスト前必須)

- 欠損バーの検出と記録 / 週末・休場データの除去
- ルックアヘッド検査:シグナル計算に「そのバーの終値確定後の情報」のみ使用
- 使用データのスプレッドと松井証券実測スプレッドの差を明記
