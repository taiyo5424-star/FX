# 01. 全体アーキテクチャ設計

## エージェント構造(6役割)と優先順位

停止権限の優先順位(上が最優先):
```
Risk Manager > AI Cost Manager > Skeptic Agent > Execution Agent
(Reviewer Agent / Research Agent は取引経路に介入しない)
```

| 役割 | 実行主体(7/8以降) | 発注権限 |
|---|---|---|
| Execution Agent | スクリプト+ルールベース | 発注**案の提示のみ**。実発注はユーザー |
| Research Agent | Fable5(週次バッチ)+スクリプト | なし |
| Risk Manager | スクリプト(閾値監視) | 停止権限のみ |
| AI Cost Manager | スクリプト(コスト集計) | NO_TRADE差し戻し権限 |
| Skeptic Agent | Fable5(候補戦略昇格時のみ) | 昇格拒否権限 |
| Reviewer Agent | ルールベース(日次)/Fable5(週次・月次) | なし |

## 取引判断パイプライン(Execution Mode)

```
[1] 前提確認(スクリプト)
    口座状態・建玉・当日損益・economic_daily_loss_jpy・残りリスク枠
    → 不明項目が1つでもあれば即 NO_TRADE
[2] 環境フィルター(スクリプト)
    イベントカレンダー / セッション / スプレッド実測 / 介入警戒フラグ
    → FAILで即 NO_TRADE(Fable5を呼ばずに終了)
[3] 戦略シグナル判定(スクリプト)
    APPROVED戦略の機械的条件のみ。status≠APPROVEDは評価対象外
[4] EV計算(スクリプト)
    docs/03の式で net_EV_R / conservative_net_EV_R を計算
[5] チェックリスト生成(スクリプト)
    docs/02の全項目。1つでもFAIL → NO_TRADE
[6] ユーザー提示 → ユーザーが発注操作
[7] 約定確認・記録(スクリプト) → logs/trades/
```

重要:[1]〜[5]は完全ルールベース。Fable5が介在するのは、
[5]で「判定不能な異常」が検出された場合の原因分析のみ(AIコストゲート適用)。

## Research Mode(週次バッチ)

```
候補生成(Fable5・バッチ1回) → IDEA記録 → バックテスト(スクリプト実行)
→ OOS/WF(スクリプト) → Skeptic審査(Fable5・昇格候補のみ)
→ PAPER_TRADE(スクリプト記録) → ユーザー承認 → MICRO_LIVE → APPROVED
```
- Research Modeからライブ発注経路への直結は存在しない(構造的に分離)。
- 研究AIコストは candidate ごとに積算し、昇格時に取引配賦額へ変換。

## データ基盤(要構築・優先度高)

| データ | 用途 | 入手方針 |
|---|---|---|
| USD/JPY 過去1分足/ティック | バックテスト | 無料ヒストリカルデータ(要調査:候補=Dukascopy等)。品質検証必須 |
| 経済指標カレンダー | イベントフィルター | 毎朝スクリプトで取得・ローカルキャッシュ |
| 実測スプレッド | コスト計算 | 松井証券画面から観測記録を蓄積(ペーパートレード期間に収集) |
| 米10年金利・DXY | レジーム/相関研究 | 研究用のみ。日次で十分 |

注意:バックテストに使うデータのスプレッドと松井証券の実スプレッドは
異なる。実測スプレッド分布を取得するまで、コストは保守側(広め)で計算する。

## 状態管理

- 全状態はファイルベース(JSON/JSONL)。メモリ内状態に依存しない。
- 日次状態ファイル `logs/daily/state_YYYY-MM-DD.json` に
  economic_daily_loss_jpy / 取引回数 / 連敗数 / AIコストを常時反映。
- セッション断・再起動時はこのファイルから復元。復元できなければ NO_TRADE。
