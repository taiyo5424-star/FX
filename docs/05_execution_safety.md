# 05. 実行系安全ルール(ブラウザ/API)

## 大前提(このシステムの実行モデル)

1. **エージェントは発注を実行しない。** 発注案(最終出力形式A)を提示し、
   実際の発注操作はユーザーが行う。エージェントの役割は
   判断・チェックリスト・照合・記録・停止判断まで。
2. **規約適合性(2026-07-06調査で確認済み、research/matsui_research.md)。**
   松井証券FX取引規程 第9条により、公式取引サイト・アプリ以外のプログラム・
   ソフトウェアによる発注は**明確に禁止**(公式API許諾事業者経由を除く)。
   第22条により違反時は通知なく新規建て停止等の対象。
   → **botによる画面自動操作での発注は規程違反であり、行わない(確定)。**
   自動執行が必要な場合は公式の自動売買(リピート注文)機能の設定を通す。
   最終的な規程解釈の確認はユーザーが行うこと。
3. 認証情報(ID・パスワード・暗証番号・認証コード)は平文保存禁止。
   エージェントが認証情報を受け取る・保持することも禁止。
   ログインは常にユーザー自身が行う。

## 推奨実行構成(リスク低い順)

| 構成 | 内容 | 位置づけ |
|---|---|---|
| A. 公式自動売買機能 | 松井証券FXのリピート系自動売買を設定画面から利用。レンジ・値幅・益出し幅・運用停止ラインを事前計算どおり設定 | **第一候補** |
| B. 半自動(提案→人間実行) | エージェントがシグナル・チェックリスト・発注案を提示、ユーザーが手動発注 | 併用(裁量系戦略) |
| C. ブラウザ自動操作での発注 | — | **不採用**(規約未確認・誤発注リスク・本システムの実行モデル外) |

## 発注前確認項目(ユーザー操作時の照合)

エージェントは事前計算値を提示し、ユーザーは注文確認画面と1対1照合する:
通貨ペア / 売買方向 / 数量 / 注文条件 / 損切り / 利確 /
(自動売買設定の場合)注文レンジ・値幅・益出し幅・運用停止ライン / 想定最大損失

**1項目でも不一致 → 発注しない。** エージェントに画面内容を報告し原因を特定する。

## 読み取り専用のブラウザ利用(許可範囲)

レート・スプレッド・建玉・注文照会・損益の**閲覧**は、ユーザーがログイン
した状態の画面をユーザー同席のもとで読み取る形でのみ行う。
以下は行わない:認証の自動化、注文ボタンのクリック、設定変更の自動操作、
セキュリティ機構の回避、隠れたバックグラウンド操作。

## 停止トリガー(即時・新規停止)

- 注文状態が確認できない / 二重送信の可能性
- 画面フリーズ / 通信エラー / セッション切れ / 再ログイン要求
- レート更新停止 / 注文結果不明
- 注文画面と事前計算の不一致 / 建玉照会と注文履歴の不一致
- economic_daily_loss_jpy >= 16,000円

停止後の再開は、原因分析完了+ユーザー承認後のみ。
**エラー後の自動再発注は禁止**(注文状態不明時の再送信は二重注文の典型原因)。

## API・第三者ツールの採用条件(将来検討)

以下すべて確認できた場合のみユーザーへ提案する(勝手に導入しない):
- 松井証券の公式提供または正式対応であることの一次情報
- 規約適合性 / 認証情報の安全な取り扱い(トークン方式等)
- 発注・照会・レートの安定性実績 / 異常時の自動停止機構
- 追加コスト込みで運用全体のnet_EVが改善すること
- Fable5常時利用を減らせること

2026-07-06時点の調査状況:松井証券FXの一般向け公式発注APIの存在は未確認。
週次研究タスクとして調査を継続(research/priority_queue.md 参照)。
